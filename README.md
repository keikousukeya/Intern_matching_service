# Intern Scout

インターン生と企業をつなぐスカウトサービスのプロトタイプです。
インターン生がプロフィールを登録し、企業がインターン生を探して直接メッセージ（スカウト）を送れます。

## 技術構成

| 領域 | 採用技術 |
|---|---|
| バックエンド | Ruby 3.4 / Rails 8.1（API モード） |
| フロントエンド | Next.js 16（App Router）/ TypeScript / Tailwind CSS |
| データベース | PostgreSQL 17 |
| 認証 | セッション Cookie（HttpOnly・SameSite=Lax） |
| テスト | RSpec / FactoryBot |
| CI | GitHub Actions（Brakeman・bundler-audit・RuboCop・RSpec・ESLint・型チェック・ビルド） |
| 開発環境 | Docker Compose |

```
ブラウザ ──▶ Next.js (localhost:3000)
               │  /api/* を rewrites で中継
               ▼
            Rails API (backend:3000 / ホストからは localhost:3001)
               │
               ▼
            PostgreSQL (db:5432)
```

Ruby や Node.js をローカルにインストールする必要はありません。

```bash

# 2. 動作確認
```

## 設計方針

### 同一オリジン化によるセッション Cookie 認証

ブラウザは Next.js（localhost:3000）の `/api/*` にだけアクセスし、Next.js の rewrites が Rails へ中継します。
ブラウザから見ると API が同一オリジンになるため、次の利点があります。

- CORS 設定が不要で、Cookie を `SameSite=Lax` のまま送れる
- セッション Cookie を `HttpOnly` にでき、JavaScript からトークンを読めない（XSS によるトークン窃取を防ぐ）
- JWT をフロント側で保存・更新する仕組みが不要

### 認証とセキュリティ

| 対策 | 内容 |
|---|---|
| パスワード | `has_secure_password`（bcrypt）でハッシュ化して保存。8〜72文字 |
| セッション固定攻撃 | ログイン・登録のたびに `reset_session` でセッション ID を作り直す |
| CSRF | ① Cookie を `SameSite=Lax` にし、他サイトからの POST に Cookie が付かないようにする ② 状態を変更するリクエスト（POST/PATCH/DELETE）は `Origin` ヘッダーが許可したオリジンと一致するものだけ受け付ける（`OriginVerification`） |
| 総当たり攻撃 | ログイン API に Rails 8 の `rate_limit` を設定（同一 IP から 3 分間に 10 回まで） |
| アカウントの列挙 | ログイン失敗時は「メールアドレスかパスワードのどちらが誤りか」を伝えない |
| メールアドレス | 小文字に正規化して保存し、大文字小文字違いの重複登録を防ぐ |
| 認可 | ロールの確認（学生一覧・詳細は企業のみ）は Rails 側で必ず行う。画面側の出し分けは表示のためだけに使う |
| プロフィールの公開範囲 | インターン生のプロフィールは企業ユーザーにのみ返す。JSON はシリアライザーで返す項目を決めており、メールアドレスは含めない |
| 他人のデータの書き換え | 自分のプロフィールの API（`/api/me/profile`）は ID を受け取らず、ログイン中のユーザーから対象を決める |
| URL による XSS | プロフィールの URL は `http` / `https` のみ受け付ける（`javascript:` URL を防ぐ）。画面側でもリンクにする前に確認する |
| メッセージの閲覧・送信 | 会話は必ず `current_user.conversations` から探すため、当事者以外は閲覧・送信・既読化ができない。存在の有無も分からないよう 403 ではなく 404 を返す |
| 新規スカウト | 新しい会話を始められるのは企業だけ（インターン生は届いた会話への返信のみ）。送信者として企業名を表示するため、企業プロフィールの登録を必須にする |
| 募集の編集・削除 | 更新・削除する募集は必ず `current_user.job_postings` から探すため、他社の募集は操作できない（404）。作成時も `company_id` は受け取らずログイン中の企業から決める |
| 非公開の募集 | 他社・インターン生からは存在も分からないよう 404 を返す。スカウトに紐づけられるのも自社の公開中で締切前の募集だけ |
| 記事の編集・削除 | 更新・削除する記事は必ず `current_user.articles` から探すため、他人の記事は操作できない（404）。作成時も `author_id` は受け取らずログイン中のユーザーから決める。下書きは本人以外には 404 |
| 記事本文（Markdown）による XSS | `react-markdown` で React の要素として組み立てる（`dangerouslySetInnerHTML` は使わない）。`skipHtml` で生の HTML（`<script>` など）は描画しない。リンクは `http` / `https` のものだけを `<a>` にし、画像は外部サーバーへ閲覧者の情報が送られないよう読み込まずにリンクとして表示する |
| 記事の書き手の情報 | 返すのは表示名（氏名・企業名）とロールだけで、メールアドレスは含めない。インターン生のプロフィールへのリンクは、閲覧者が企業のときだけ表示する（プロフィールの公開範囲は今までどおり企業のみ） |

許可するオリジンは環境変数 `FRONTEND_ORIGINS`（カンマ区切り、既定値 `http://localhost:3000`）で設定します。

### プロフィールの設計

- **登録時の入力は最小限**: 新規登録はメール・パスワード・区分だけにし、登録後にプロフィール入力画面へ案内する。途中で離脱されにくくするため。
- **企業が重視する項目で比べられる一覧**: 一覧カードにはスキル・希望期間・志望職種を表示し、企業が一目で比べられるようにした。
- **スキルは候補つき自由入力**: スキルはマスタ（`skills`）と中間テーブル（`student_skills`）で管理する。入力中は既存のスキルを候補に出し、候補に無いスキルもそのまま登録できる。
  `React` と `react` は同じスキルとして扱い（小文字化した値に一意インデックス）、表記ゆれで検索（F-04）しにくくなるのを防ぐ。
  候補はブラウザ標準の `<datalist>` ではなく独自の候補リスト（WAI-ARIA の combobox）で出す。矢印キー・Enter で選べ、入力した文字に一致する部分を太字にし、候補に無いスキルは「新しく追加」から登録できる。
  入力しなくても選べるよう、よく使われているスキル（上位 20 個）を「言語」「フレームワーク」「インフラ・ツール」「デザイン」「その他」に分けて並べ、クリックで追加・もう一度押すと外せる。
  分類は `skills.category` に持ち、よく使われるスキル名との対応表（`Skill::CATEGORY_BY_NAME`）から作成時に自動で決める。表に無いスキルは「その他」になるため、自由入力はこれまでどおりできる。プロフィール・募集・記事の入力と各検索フォームの 6 か所で共通の部品（`SkillInput`）を使う。
- **N+1 の回避とページネーション**: 一覧は `includes(:skills)` でスキルをまとめて読み込み、20 件ずつ返す。

### インターン生検索の設計（F-04）

- **絞り込み条件**: キーワード・スキル・大学・卒業予定年・志望職種。指定した条件どうしは AND で組み合わせる。
  - キーワード: 氏名・大学・学部・志望職種・自己紹介・スキル名の部分一致。スペース（全角も可）で区切った複数の語は、すべてを含む人に絞り込む
  - スキル: 大文字小文字を区別しない完全一致。「すべて持つ（AND）」と「いずれかを持つ（OR）」を切り替えられる
  - 大学・志望職種は部分一致（「東都」で「東都大学」がヒット）、卒業予定年は完全一致
- **並び順**: 新着順（登録日時）／更新順（プロフィールの更新日時）。
- **重複と件数**: 結合（JOIN）ではなくサブクエリで絞り込むため、同じ人が重複して返らず、ページネーションの件数もそのまま正しく数えられる。
- **SQL インジェクション対策**: 値はプレースホルダーまたは Arel で渡す。`%` や `_` はワイルドカードとして扱わないようエスケープする。
- **重い検索の防止**: キーワードは 5 語・各 50 文字、スキルは 10 個まで。不正な値（数値でない年・未知の並び順など）は無視して既定値で検索する。
- **検索条件は URL に持つ**: `/students?q=…&skills=Ruby&skills=React&skill_match=any` のように URL に反映するため、再読み込み・ブラウザの戻る・URL の共有でも同じ結果になる。
  入力中は API を呼ばず、「検索する」を押したときに反映する。

### 募集掲載の設計（F-03）

- **インターン生が比べたい項目を一覧に出す**: 業務内容・期間・報酬・勤務形態（リモート／ハイブリッド／出社）・締切・必要スキルを一覧のカードに表示する。
- **期間は日付、報酬は自由記述**: 期間は開始日・終了日で持ち、インターン生の希望期間と同じ形式で比べられるようにした。報酬は「時給 1,500 円」「月 12 万円（週 4 日）」など形態がさまざまなため自由記述にした。
- **必要スキルはインターン生と同じスキルのマスタを使う**: `job_posting_skills` で `skills` に紐づけ、`React` と `react` を同じスキルとして扱う。スキル名で登録する処理は `SkillTaggable`（concern）にまとめ、インターン生プロフィールと共通にした。
- **公開範囲**: 公開中の募集はログインユーザー全員（インターン生・企業）が閲覧できる。非公開の募集は作成した企業だけが見られ、他のユーザーには 404 を返す（存在も分からないようにするため）。
- **締切**: 一覧には公開中で締切前（締切当日まで）の募集だけを出す。締切を過ぎた募集も、スカウトのリンクから詳細は見られるようにして「締切済み」と表示する。締切に過去の日付は設定できない。
- **新着順は公開日時**: 非公開→公開にした日時（`published_at`）で並べる。作成日時にすると、下書きのまま置いていた募集が古い扱いになってしまうため。
- **募集に紐づけたスカウト**: メッセージに `job_posting_id`（任意）を持たせ、吹き出しの下に募集のカードを表示する。紐づけられるのは送信者の企業自身の公開中で締切前の募集だけで、モデルで検証する。
  会話は今までどおり企業×インターン生で 1 件のままにし、同じ会話の中で別の募集を紹介することもできる。
- **削除**: 募集を削除しても、送信済みのスカウトのメッセージは残し、紐づけだけを外す（外部キーも `on_delete: :nullify`）。

### 技術ブログの設計（追加機能）

- **ねらい**: インターン生は学んだことを発信して技術力を伝え、企業は技術への取り組みや開発チームの様子を伝える。
  スカウト型のサービスでは「プロフィールや自己申告のスキルだけでは技術力が分かりにくい」「インターン生が企業を知る材料が少ない」ため、その両方を補う。
- **インターン生・企業のどちらも書ける**: `articles.author_id` は `users` を参照し、ロールを問わない。書き手として名前を表示するため、プロフィールの登録を必須にした。
- **公開範囲**: 公開中の記事はログインユーザー全員が閲覧できる。下書きは書いた本人だけが見られる。
- **本文は Markdown**: 見出し・コードブロック・表・チェックリスト（GFM）が使える。編集画面に「プレビュー」を用意した。保存は Markdown のまま行い、表示時にフロントエンドで変換する（XSS 対策は「認証とセキュリティ」を参照）。
- **タグはスキルのマスタを使う**: `article_skills` で `skills` に紐づけ、インターン生のスキル・募集の必要スキルと表記をそろえる（`SkillTaggable` を共通で利用。5 個まで）。
- **既存の画面とのつながり**: インターン生詳細（企業向け）と企業詳細に、その人が書いた公開中の記事を表示する。企業はスカウトする前に技術力を確認でき、インターン生は企業の技術への取り組みを知れる。
- **一覧と検索**: 新着順（公開日時）。キーワード（タイトル・本文・タグ・書いた人の名前）・タグ（AND／OR）・書いた人の区分（インターン生／企業）で絞り込める。条件は募集・インターン生の検索と同じく URL に持つ。
  一覧では本文の代わりに、Markdown の記号やコードブロックを除いた抜粋（120 文字）を返し、レスポンスを軽くしている。

### メッセージの設計

- **テーブル**: `conversations`（会話）・`conversation_participants`（参加者と既読位置）・`messages`。
  仕様書の `threads` は Ruby 組み込みの `Thread` クラスと名前が衝突するため `conversations` とした。
- **企業×インターン生で 1 スレッド**: `conversations` に `company_id`・`student_id` を持たせ、組み合わせに一意インデックスを張って DB でも保証する。
  同じインターン生に 2 通目を送ると既存の会話に追加される。同時に作成された場合も一意制約で検知し、先にできた会話を使う。
- **参加者テーブル方式**: 参加者を多対多にしておき、グループチャット（F-06）に拡張できるようにした。
- **未読／既読**: 参加者ごとに `last_read_at` を持ち、それより後に届いた相手のメッセージを未読とする。
  閲覧（GET）は副作用を持たせず、画面が `PUT /read` を呼んで既読にする。自分が送信したときは自分の既読位置も進める。
- **N+1 の回避**: 一覧の未読数と最新メッセージは、会話ごとに数えず 1 回の SQL でまとめて取得する。会話の並び順用に `last_message_at` を持つ。
- **リアルタイム性**: SWR のポーリングで取得する（会話画面 5 秒・一覧 15 秒・ヘッダーの未読数 30 秒。タブが非表示の間は止まる）。
- **日時**: 端末の設定に関係なく JST で表示する。

### マイページとヘッダーの設計（UI 改善）

- **マイページ（`/mypage`）に自分の情報をまとめる**: ログイン後に「自分について確認・対応すること」を 1 画面で見られるようにした。
  - プロフィールの概要と入力状況（何項目中何項目入力済みかのバーと、未入力の項目の一覧）。未入力の項目を見せることで、スカウトにつながるプロフィールの充実を促す
  - 未読がある会話（最新の会話 20 件のうち未読があるものを最大 5 件）と未読の合計
  - 自分の記事（下書きを含む更新の新しい順に 5 件）と、企業は自社の募集（非公開・締切済みも含めて 5 件）。状態のラベルと「編集」を付け、各管理画面へのリンクも置く
  - 既存の API（`/me/profile`・`/me/articles`・`/me/job_postings`・`/conversations`）をそのまま使い、バックエンドは変更していない。欄ごとに別々に取得するため、1 つが読み込めなくても他の欄は表示される
- **ヘッダーのリンクを 4 つに絞る**: 「プロフィール」「募集管理」をマイページにまとめ、インターン生は「募集を探す／技術ブログ／メッセージ／マイページ」、企業は「インターン生を探す／技術ブログ／メッセージ／マイページ」にした。
  マイページ配下の画面（プロフィール編集・記事管理・募集管理）を表示中も「マイページ」を強調し、各画面の見出しの上に「← マイページへ戻る」を置く。
- **スマホ幅ではメニューを開閉式にする**: md 未満では「メニュー」ボタン（`aria-expanded`・`aria-controls`）で開閉し、リンクを押す・Esc で閉じる。閉じていても未読の件数はボタンに表示する。

### トップページのおすすめ（UI 改善）

- **ログイン後のトップページをホームにする**: 未ログインではこれまでどおりサービスの紹介と登録・ログインの導線を出し、ログイン後は「ホーム」として、プロフィール未登録の案内・未読メッセージの案内と、おすすめを表示する。
- **おすすめの内容**
  - インターン生: 自分のスキルを含む新着の募集・記事
  - 企業: 自社の募集の必要スキル（公開中で締切前の募集のスキルを優先）に合う新着のインターン生・記事
  - 各欄 4 件。カードの上に「スキルが一致: Ruby・React」または「新着」を表示し、なぜ表示されているかが分かるようにした。自分の記事はおすすめに出さない
- **既存の検索 API で作る**: `skills[]` と `skill_match=any` で「スキルのいずれかを含むもの」を取得する。バックエンドは変更していない。
  - そのため並びは「一致するスキルの数が多い順」ではなく新着順になる
  - 検索に使えるスキルは 10 個まで（API の上限）なので、それを超えたら先頭の 10 個を使う
  - 合うものが 4 件に満たないときは、新着順の一覧で埋める（同じものは 1 回だけ出す）。足りているときは新着の一覧を取得しない
  - スキルが登録されていないときは新着順だけを表示し、スキルの登録（企業は募集の作成）への案内を出す
- 各欄の下に「スキルで絞り込んだ一覧」（検索画面に同じ条件を入れた URL）と「すべて見る」へのリンクを置く。

## API 一覧

| メソッド | パス | 内容 | 認証 |
|---|---|---|---|
| POST | `/api/registration` | 新規登録（`role`: `student` / `company`）。成功するとログイン状態になる | 不要 |
